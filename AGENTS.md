# Architecture Contracts & Agent Guidelines (`AGENTS.md`)

This document defines the invariants, execution models, verification contracts and
live-testing procedure of `vsockscan`. Contributors and automated agents modifying
this codebase must adhere strictly to these principles.

---

## The Four Core Repository Tenets

### Tenet 1: Every Verdict Carries Its Basis
- **Honest negatives:** the tool exists for the shape where the answer is "there is
  nothing here" - a guest whose kernel never enabled a vsock device. A negative is a
  result, not a shrug: each signal is reported with the basis for its verdict, and
  `probe` never guesses state it lacks privilege to read.
- **The taxonomy is the product.** Row kinds (`open`, `closed`, `refused-kernel`,
  `loopback-redirect`, `unsupported`, `absent`, `denied`, `stale`, `not-muxer`,
  `silent`) are load-bearing vocabulary pinned by the README, tests and renderers.
  Renaming or folding a kind is a breaking change. The stage of a failed attempt
  decides an errno's meaning (see `kind_for_errno`): pre-connect errnos are answers
  about the *socket file* (`ENOENT`/`ENOTDIR` = `absent`, connect-time
  `ECONNREFUSED` = `stale`), post-connect errnos are the far end refusing
  (`EPIPE`/`ECONNRESET`/`ECONNABORTED` = `closed`). Never collapse the stages.
- **A closed answer without an errno is the muxer's own answer.** In `h2g`, a guest
  that refused arrives as the handshake's word, not as EOF/`ECONNRESET`; an errno on
  a closed row means the *channel* broke and must be reported, never laundered into
  `closed`.
- **Noise statements are precise.** `h2g`'s noise disclosure says what actually
  happened (one local AF_UNIX connect per port *plus* local AF_VSOCK classification
  probes) and never claims traffic that did not leave the host - or denies traffic
  that did. The preflight canary (`CONNECT` answered on a random high port) is a
  finding about a forwarder, surfaced as a warning, never silently swept.

### Tenet 2: Machine Formats Are Exhaustive, Human Output Is Dense
- `json`/`yaml` carry every probe row, note and finding; `text` renders the same
  model at terminal density. `--json-schema` is a standalone escape hatch that must
  work with no subcommand.
- **Colour contract:** stripping SGR from a coloured render is byte-identical to the
  plain render for `text` and `yaml`, valid JSON for `json`, and Markdown is
  colour-optional. Layout padding is written as `format!` widths, never as runs of
  spaces inside message strings - `tests/source_hygiene.rs` enforces this.
- **Renderer fields are append-only.** `probes[].name`, `outcome.kind`,
  `summary.by-outcome`, `summary.results` are stable keys; tools parse them.

### Tenet 3: Non-Destructive, Ring-3-by-Default Recon
- **Zero state mutation on the host kernel:** no module insertion, no interception,
  no relaying or capturing. `listen --census` distinguishes `EACCES` (privilege) from
  `EADDRINUSE` (occupied) by binding only; the byte preview covers connections this
  process itself accepted. `tests/source_hygiene.rs` asserts the absence of any
  interception machinery so the claim cannot rot.
- **Privileged surfaces are opt-in:** `--mmio` (`/dev/mem`, `CAP_SYS_ADMIN` +
  `iomem=relaxed`) is off by default and its failure is never reported as "no
  device".
- **h2g speaks only valid handshake text.** Malformed port requests poke the muxer's
  bookkeeping against the guest and are never generated by a scan.

### Tenet 4: The Binary Is the Deliverable
- Static musl by default: it must run in a rootfs with no glibc guarantee, no
  `/lib/modules`, no package manager. `.cargo/config.toml` pins
  `x86_64-unknown-linux-musl` + `+crt-static`; release profile is size-cut
  (`opt-level="z"`, `lto`, `panic="abort"`, `strip`).
- **`src/uapi.rs` constants are measured facts, not folklore.** They were verified
  in three kernel environments and each carries its provenance. Do not "modernise"
  them from blog posts - e.g. `NETLINK_SOCK_DIAG = 4`; 18 is `NETLINK_ECRYPTFS`
  whose handler answers `-EBADMSG`. New constants need a measurement record, not a
  citation of another header.

## Exit-Code Contract (spec §4)

| code | meaning |
|---|---|
| `0` | clean run (also `--help`/`--version`) |
| `1` | usage error - the *operator's* argument is wrong, validator-only, never the target's fault |
| `2` | runtime error, including every h2g preflight abort (`absent`/`denied`/`stale` uds paths exit here, leading with the taxonomy word) |
| `3` | selftest assertion failure - the tool disagrees with itself |
| `130` | SIGINT: the report for whatever completed is still printed, then this code |

`--cid` is required for `scan` (no implicit default: a run can never be pointed at
hypervisor keyspace by forgetting an argument); `--parallel` is bounded `1..=256`
because the muxer's table is 1023 slots shared with the guest.

## Module Map

`main.rs` (dispatch, exit codes, SIGINT) · `probe` / `scan` / `listen` / `h2g` /
`selftest` (commands) · `muxer` (host-side CONNECT/OK client, bounded
`O_NONBLOCK` connect + poll + `SO_ERROR` - a wedged muxer must not hang us) ·
`diag` (`vsock_diag` netlink census) · `kernconfig` (`/proc/config.gz` + fallbacks, pure-Rust gunzip) ·
`caps`, `spec` (port/CID parsers), `model` (report, shared note builders) ·
`uapi` (measured constants) · `render/{text,markdown,json,yaml}`.

`summary.results` in h2g is the **pre-filter** count; `--open` filters rows, never
results, and renderers must not recompute it afterwards.

## Verification: Definition of Done

```sh
cargo test --release                                  # 146 unit + 19 integration
cargo clippy --release --all-targets -- -D warnings
cargo fmt --check
shellcheck -S warning scripts/*.sh
```

- The suite includes `h2g` end-to-end against a **fake muxer** (handshake rows, JSON
  shape, `--open` counts, preflight aborts) and `selftest`'s nine loopback checks
  that prove the outcome classifier with no device and no host.
- Tests pin behaviour a consumer can observe, not prose. If an assertion only
  re-states a message string or a mock echo, delete it rather than maintain it.
- A change to the taxonomy, exit codes or the h2g handshake is not done until the
  live fixture also passes (below) - the fakes encode *our* reading of the protocol;
  only a real muxer checks the reading.

## Live Verification vs a Real Firecracker Muxer

`scripts/live-firecracker.sh` boots a throwaway microVM (guest CID 3, vsock UDS)
whose init runs `vsockscan listen --ports 1235`, then asserts the `h2g` contract
from the host through a **real** CONNECT/OK muxer. You do not need to read the
script to use it:

```sh
scripts/live-firecracker.sh check                     # "available" (0) | "unavailable: <why>" (3)
scripts/live-firecracker.sh setup [--system]          # fetch assets; --system = sudo chmod /dev/kvm (CI)
scripts/live-firecracker.sh run [--skip-unavailable]  # one boot, four checks; console -> target/live-firecracker/
```

- **Exit code semantics:** `run` PASS = the *script's own* exit status is 0 after
  `ok x4 ... PASS`. Judge `$?` of the script, never of a pipeline it is piped into.
  A box without usable `/dev/kvm` is "not testable": `--skip-unavailable` prints
  `skipped: <why>` and exits 0; without the flag it exits 3. Never fabricate a
  result for a skipped box.
- `BIN` unset: builds the working tree (musl release; cargo's no-op is sub-second),
  so the fixture always tests what you just changed. `BIN=path` tests that binary.
  Other knobs: `VSOCKSCAN_LIVE_CACHE` (default `~/.cache/vsockscan/live-firecracker`),
  `FC_TIMEOUT` (boot budget, 90 s), `KEEP=1` (retain the work dir), `OUT`.
- **Battery (4 checks):** open row carries a host port from the stock 2^30 muxer
  pool; closed row answers without errno; `--open` keeps 1-of-2 with the honest
  count note; absent uds paths exit 2 via *both* `ENOENT` and `ENOTDIR` (a path
  walked through the live socket file - the classic jailer mix-up - is `absent` too).
- **Assets** (cached once, rootless): Firecracker v1.17.0; matched Firecracker-CI
  kernel `vmlinux-6.1.176` (its published config has `CONFIG_VIRTIO_VSOCKETS=y` -
  no guest module loading - and both `VSOCKETS_LOOPBACK` and `VSOCKETS_DIAG` unset,
  the exact kernel shape this tool targets); `ubuntu-24.04.squashfs` converted to
  ext4 with `unsquashfs` + `mkfs.ext4 -d` (no loop device, no root). The cached
  rootfs is never mutated: each boot copies it with `cp --reflink=auto`.
- **Guest plumbing:** PID 1 is `/bin/sh -- /dev/vdb` (script drive, sector-padded
  with newlines - the shell must never parse NULs); the scanner travels on raw drive
  `vdc` and is extracted with `head -c <size>`; readiness markers land on the serial
  console, which the host tails. One boot per invocation, ~2 s.

### Gotchas learned the expensive way
- **EXIT traps run at top level.** A variable the trap reads must not be `local` to
  the function that installed it: under `set -u` cleanup aborts *after* a green run
  and the exit code says 1. `fc_pid` is global on purpose.
- The runner contract is stricter than local habits: run the script directly and
  echo its status when verifying.
- `/dev/kvm` read/write is the only privilege needed locally; GitHub's
  `ubuntu-latest` runners do expose it - expect the CI leg to actually boot, and
  keep the skip path honest for everything else.

## CI

- `ci.yml`: fmt + clippy + tests on every push/PR.
- `rust.yml`: musl release matrix, artifact per target.
- `live-firecracker.yml`: build the musl binary, then one live leg:
  `setup --system` (installs `squashfs-tools e2fsprogs`, opens `/dev/kvm`) →
  `BIN=bin/vsockscan run --skip-unavailable` → upload `target/live-firecracker/`
  (guest console) always. Actions are SHA-pinned; `dependabot.yml` keeps refs
  current.

## Housekeeping

- `target/`, the guest-console artifact dir and the agent session ledger are ignored;
  never commit them.
- Prose in `src/` comments states *why* an invariant exists and what broke when it
  did not; a comment that re-describes the next line is noise. Message strings obey
  the space-run rule above.
- README sections "Provenance", "Limits, stated rather than discovered" and the
  command table are contracts with the operator; update them in the same commit as
  the behaviour they describe.
